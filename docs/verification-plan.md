## B. Python demo 实机基线（T-017 至 T-020 已完成）

以下步骤须在用户打开灯组并能直接观察 `D1–D23` 后执行。按顺序执行；每一步只运行一次。设备名称应为“极梦匠”，本机 CoreBluetooth 标识符应为 `1BAA3B72-5D5A-32C5-0FD6-4B579EE6566C`。该标识符不是蓝牙 MAC 地址。

| 编号 | 操作 | 需要记录的结果 |
| --- | --- | --- |
| T-017 | 打开电源，先不连接 BLE。 | 供电来源及额定值（若可见）；蓝色指示灯；23 颗灯珠是否短暂亮起、颜色与持续时间。 |
| T-018 | 执行下面的 `scan`。该命令不连接设备。 | 广播名和本机标识符是否同时匹配。 |
| T-019 | 执行下面的 `list --kind 30`。 | GATT 核对结果、写入 API 结果、完整通知；灯珠有无变化。既有样本为 `CC 30 00 00 55`，不能要求设备永远返回该值。 |
| T-020 | 执行下面的 `preview`，只给 `D1` 发送一次红光临时试色。 | 实际 TX/RX、亮起的 D 编号、颜色、约持续时间、断开后的状态及异常。 |

```bash
uv run python -m model_light scan --id 1BAA3B72-5D5A-32C5-0FD6-4B579EE6566C
uv run python -m model_light list --id 1BAA3B72-5D5A-32C5-0FD6-4B579EE6566C --kind 30
uv run python -m model_light preview --id 1BAA3B72-5D5A-32C5-0FD6-4B579EE6566C --target D1 --rgb FF0000 --brightness 10
```

T-020 的预期发送字节是 `BC 33 01 09 00 01 00 00 FF 00 00 0A 00 55`。这是已实测的 D1 红光请求，且已与 demo 组包器的离线输出逐字节核对。执行后核对日志中的实际请求。若广播名、标识符、GATT 属性或请求字节不符，停止并查明原因。
