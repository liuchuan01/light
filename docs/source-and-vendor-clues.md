## 外部产品操作线索

与“极梦匠”相关的[灯组教程搜索结果](https://www.douyin.com/shipin/7613603740389787698)包含平台自动生成的文字稿。该文字稿描述：首次使用时调整亮度、选择灯效后保存，再返回列表打开开关；随后可设置局部编组和高级预设。文字稿还提到主体有 23 颗灯珠，以及后续可能提供安装包或光效更新。网页的直接打开结果与搜索摘要不一致；本项目没有人工核对视频画面、发布日期、作者身份和具体灯组版本。因此这些内容只列为**待核对线索**。

旧 APK 的命令区分 `33/43` 临时试色、`32/42/53` 保存，以及 `44/56` 切换全身或高级预设。局部预设在旧 APK 中没有单独的切换命令。上述文字稿的操作顺序与代码分层相符，但不能据此证明当前设备已保存预设，也不能解释全部临时试色的熄灯原因。当前实机列表响应在试色前后数量字段均为 `0`，只说明按 APK 的偏移规则可见列表没有变化。

另一条[较早的极梦匠视频说明](https://www.bilibili.com/video/BV16yyyBTEeD/)提到眼部与下巴可能并联，以及曾考虑修改 PCB。该说明发表于产品较早阶段，不能直接套用到本台灯组。它提示：协议点位与模型内的发光部位可能不是一对一关系；本台实物仍以 `D1–D23` 的现场观察为准。

## 后续取得其他 APK 时的离线比对顺序

1. 保留新旧原始 APK，并计算各自 SHA-256。
2. 比较签名证书指纹、包名、版本、构建状态和权限。
3. 比较启动路径、BLE 服务与特征、命令号、收发字段和响应解析。
4. 对新增灯效、保存流程、设备升级入口分别列出代码证据。
5. 先完成离线核对，再安排实机验证。不得把新 APK 中可编码的功能直接写成当前固件能力。
